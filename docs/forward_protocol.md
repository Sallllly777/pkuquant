# 冻结后的前向观察

冻结时间见 `config/freeze_manifest.json`（本地 UTC 时间及哈希）。截至本次本地整改，没有冻结之后完成的股票交易日信号/收益对，不能写成前测已完成。老师截图没有给出最低交易日数，不能自行宣布若干天即可满足统计检验。

1. 保持冻结代码、股票池、名单、参数和费用不变。每个实际股票交易日收盘后取同一来源的日线，保留暖机记录、获取时间、复权口径及 SHA-256；不要用未来修订数据替换已存输入。
2. 当天运行 `research_control.py forward` 记录信号。只接受“冻结后、当日已收盘”的数据终点；重复日期拒绝覆盖。文件写入 `runs/forward_v2/YYYY-MM-DD.json`，含完整横截面分数和目标权重。
3. 下一实际交易日开盘后，另行保存行情、可交易状态、成交假设与成本。再下一个开盘才能得到一段对应的组合持有收益；不要把当晚 SimNow 期货成交混作股票因子样本。
4. 收益核算只能读取已经在当时登记的信号文件；不能补填缺失信号或根据后来涨跌改变权重。`scripts/evaluate_forward.py` 只读取已登记分数，按冻结核心计算逐开盘净值、费用和末期退出；拒绝开盘后补填信号。缺失信号日保持缺失并生成持币目标，不重新计算补选。该入口已有合成数据边界测试，但尚无真实未来样本可作实测验收，输出仍是价格代理而非实际成交账单。
5. 汇总覆盖率、持币/拒绝交易原因、成本前后收益、只多与基线比较。样本长度和检验功效不足时写“待观察”，不强求正收益或显著性。

这项工作需要实际时间流逝与数据获取；一次历史回测或把历史 CSV 的日期改晚都不能代替。用户已授权 10 月 13–15 日每天 21:00 定时采集，具体执行与收尾见[前向操作说明](forward_operations.md)。不自动下单。

有实际样本后运行：

```powershell
python -B scripts/evaluate_forward.py --signals runs/forward_v2 --input data/latest_daily.csv --output runs/forward_review_YYYYMMDD
```

每次使用新输出目录；保存输入和信号哈希。至少需要信号日和随后两个实际开盘日期。
